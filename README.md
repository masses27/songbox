# 听歌小窝（songbox）

给家里那位用的安卓音乐 App：界面照网易云，全程不登录任何账号。网易云、QQ、B 站、酷狗四个曲库都走端内匿名直连、能出整首，酷我如今只剩歌词和搜索。

## 曲库现状（2026-10 实测）

| 源 | 匿名能给的 | 备注 |
| --- | --- | --- |
| 网易云 `wy` | 整首，最高 320k | `fee=1` 撞会员墙；weapi 签名在本机算 |
| QQ `tx` | 整首，只有 128k | 游客身份只开 M500；`payplay` 先判这首歌放不放得出来 |
| B 站 `bl` | 整首，上限 192k | 会员墙后面第一条还肯匿名出整首的路；直链必须带 Referer |
| 酷狗 `kg` | 整首，只有 128k | `i/v2` 匿名直链，会员墙后面的第二条路；老的 `v5/url` 要 sso-code，接不了 |
| 酷我 `kw` | 歌词、搜索 | 音频接口现在只回 11 秒试听 |

放不出时先降一档音质，再去四个源里找同一首歌（`lib/ui/pages/builtin_library.dart`，端内可取的四个源写死在 `inAppSources`）。「确认没有免费版」这个判定只在接口明确答「没有」时才落盘；断网、被风控一律算「这次问得不凑巧」，不会把一首好歌跳过一周。

0.8.41 删掉了 lx-music v2.0.0 音源脚本那一整层（QuickJS 沙箱、8 个内置脚本、音源管理页、自动更新）。留着的唯一理由是「酷我独占曲目还能靠脚本出整首」，而那一层自己那条路早就断了：内置 8 个后端逐个探过、还能出链的没几个，App 里的「全部更新」只能换新脚本文件、救不了已经下架的接口；桌面上每次冷启动都记一行「音源脚本激活失败（20 秒内没有就绪）」。删掉之后酷我的歌照样能听——去别的曲库找同一首，那条路本来就在；顺手撤掉的是酷我占着的那一格换源名额（候选最多两条）和「找其他版本」里那一条点下去没声音的候选。代价是以后再接第三方曲库要自己写端内模块；换来的是 0.8.39 那份 arm64 APK 里 1,050,688 字节的 `libfastdev_quickjs_runtime.so` 和 `assets/js` 那 473,036 字节（引导 + 8 个脚本）一并没了。

## 功能

搜索（单曲/歌手/专辑/歌单，分页 + 历史 + 模糊）、首页推荐、发现页（按本机口味的另一排 + 新歌速递 + 新碟上架 + 热门歌手 + 分类歌单 + 三个源的榜单）、按本机听歌数据挑的每日推荐、自建歌单与收藏、播放页黑胶 + 滚动歌词（含翻译行）、播放历史与统计、后台播放（通知栏/锁屏/线控/下拉播放卡，卡上「上一首/下一首」走的就是应用里那同一对方法）、下载、均衡器、定时停止、断网等一等再重试（半路停住的那首要在同一首上停满两趟才去重取一条地址——省电策略掐掉后台网络几秒是常事，同一地址本来就会回来，而重取会连换源记住的那个版本一起忘掉；本机那份放不出就自动改走在线的，等满几轮才报错跳下一首；换歌、连着播出够久、她自己按过重试，这三种才重新发满额度）、进度兜底（播完没回话、半路停住不往前，都有一只自己的表盯着接着放；那只表只认往前走、而且往前走的速度跟得上墙上时钟的位置，还要播放器自己也摆出放完的样子才按「放完了」放行——内核报晚了一步跨到末尾的那种脏值不收，收下表就再也退不回来，往后每首都像贴在末尾、六秒一跳把队列推走，听着正是「只播一点点就自己跳歌」）、曲库自检、播放卡自检与一键修复、日志导出。

界面这一层有两条规矩：能自动办的不留按钮，非要她出手时动作就放在提示条上（「换版本」「重试」「接着放」「撤销」），不指路设置页；本机数据没落盘、某一页没拉到、歌中途停了，都要当场在屏幕上说出来，不靠她去猜。循环模式跟音质、主题一样存进设置，重启不回列表循环。

弹层（对话框、底部面板、菜单、提示条）走主题里的半透明底（92% 不透明度）并各限宽度——对话框 420、底部面板 560、提示条 480，桌面大屏不会铺满一屏；播放页无论设置是深是浅都用深色一套局部主题，黑底上不再跳出一块白面板。播放条上的循环模式从「点一下换一种」改成直接摊开四个选项（列表循环/单曲循环/随机播放/播完停止），选完不动当前曲目也不重新起播，窄屏和大字号下自动换成两行、按钮仍是 48×48。

发现页从上到下是「按你的口味 · 新歌速递 · 新碟上架 · 热门歌手 · 歌单分类 · 榜单」。

第一排只在她的本机听出偏好之后才出现：拿口味里最重的三位歌手，各自在网易云搜一批（一位 20 首），只留下真挂着那位署名的（按歌手名搜出来的东西里混着撞名的、翻唱的、合集里塞的），再把她已收藏的、听厌的、这三天刚听过的拿掉，一位一首轮着排——一位连取十二首，那一排就成了一个人的精选集，另外两位白搜。这一排是顺手点的，所以能一按就出声的排前面（不是会员墙的歌，以及本机已经备好一份免费版的会员歌），还要绕整条换源链子才出声的排后面——塞满后面那个的话，她的感受就是「怎么点三首有两首在转圈」。这台机器上一个播放记录都没有时，整块不占那一格，而不是摆一个「没拉到」。

中间三块是这一轮新加的横向板块，都用同一个组件（`_Strip`）：进来自己取一次、跟着父页下拉刷新重取、「换一批」往后挪一屏（12 个）、挪到头绕回第一批、坏了只在这一格里说一声并给一颗重试。数据都是网易云那三条匿名接口，各自「换一批」的底气不一样：

- **新歌速递**一次回 100 首（去重后正好 100）。`area` 和 `offset` 都是摆设——2026-10-29 拿 7/96/8/16/0/ZH 六个值各打一次，与 `ALL` 那批的交集全是 100/100，`offset=12` 也一样——所以它不重发请求，「换一批」是在这一百首里切窗口：一屏 12 首，头八屏满、第九屏只剩 4 首，再点一次绕回第一批。响应里唯一带 time 的字段 `hearTime` 一百条全是 0，界面上没有可比的时间，于是这块只叫「新歌速递」，不写「按发行时间排」。
- **新碟上架**的 `offset` 是真翻页（连打 0/12/24 三批、每批 12 张，相邻两批一张都不重）。地区那六颗胶囊逐个用 id 集合量过：`EA`/`JP`/`KR`/`OTHER` 与「全部」分别只重样 1/1/0/0 张，是真换了四批碟；写错的词（`EU`、`A`）网易云不报错，交回来的正是「全部」那 20 张（20/20 全重），所以词表只能照接口认的那些写。「华语」是这颗唯一挨着「全部」的——20 张里 18 张相同（同一档连打两次是 20/20 全重，所以那 2 张的差不是接口抖动），点下去换不掉一屏，所以它排在「全部」后面而不是当默认档。
- **热门歌手**同样认 `offset`（0/12/24 三批、每批 12 位，相邻两批一位都不重），但不给按地区筛：加 `area`/`cat`/`type` 一律回 400，所以这一格一颗筛选胶囊都没有。

歌单分类那一排词表是端内带的 70 个词（`lib/music_sdk/wy_catalog.dart`）：抄的是官方分类树 `/api/playlist/catalogue`（匿名读得到，语种 5 / 风格 23 / 场景 12 / 情感 12 / 主题 18），但**树上写着不等于分类页有货**——网易云对未知分类不报错，直接回一张兜底歌单（首条恒为 `6671216522`，`total=500`），点中一个死词看到的是「拉到了十几张歌单」，内容跟这个分类毫无关系。所以每一个带进来的词都单独打一次 `/api/playlist/list` 验过（2026-10-29，每问隔 700ms、先立两个瞎写的词当对照）。装机的那版（0.8.39）带的是 57 个词，这一轮先照官方树补齐成 85 个候选，逐条复核下来**旧那 57 个里就有 20 个是这种死词**（小语种/法语/德语/意大利语/西班牙语/俄语/泰语/R&B/唱作/睡眠/开车/深夜/聚会/动漫/励志/网络热歌/男声/女声/纯音乐/儿歌——它们全都不在官方树上，是从别的 App 的分类页抄来的样子），全部删掉，再补上树上剩下验过真有货的 5 个（`ACG`、`网络歌曲`、`经典`、`R&B/Soul`、`驾车`，其中四颗正是那些死词的正版写法：`R&B`→`R&B/Soul`、`动漫`→`ACG`、`开车`→`驾车`、`网络热歌`→`网络歌曲`）。净数 57→70，而这 70 个现在正好是那棵树本身，以后网易云加新分类照着树抄就行，只是每颗还是得自己打一次。这 20 个死词在测试里钉成一张黑名单，因为它们在界面上看着都「像分类」，下次照着别的 App 抄很容易顺手塞回来。「全部分类」摊开的那一块是一团小胶囊：这里的 `_CatChip` 不能用 `Container(alignment:)`，那会让每颗撑满整行宽、70 个词竖着一行一个（360 宽的测试屏上量到面板 2480 高，换成 `Row(mainAxisSize: min)` 之后是 678）。

这一条接口真的认 `offset`（华语连打 0/12/24 三页，12 首一组基本不重样），所以每一类都能「换一批」，不只「推荐」那一格。排序那一档这一轮做了又删掉：2026-10-29 拿华语/摇滚各打了 `hot`/`collect`/`new`/一个瞎写的词四轮，`collect` 换出来的确实是另一批，可它并不按收藏数排（华语/collect 头一条收藏 738、第六条 13 万），`hot` 也不按播放数排（头一条 85 万、第五条 1530 万），`new` 直接回空（`total=0`），乱写的值回的是第三套谁也对不上的榜。四个值没有一个是它名义上那个意思，摆两颗「最热」「收藏最多」等于让她信一个会说谎的开关，所以界面上只留「换一批」，请求里恒定发 `order: hot`。

榜单有三个源：网易云、酷我，和这一轮接进来的 QQ 音乐（`lib/music_sdk/tx_leaderboard.dart`，全程匿名）。接那一家不是为了多几个榜名：榜单和取链同域名 `u.y.qq.com`，那两个搜索域名同时回 HTTP 500 的那段日子这条还是通的。它的总表给 4 组共 30 张榜，代码剔掉唯一不放声音的 MV 榜（`topId=201`）留 29 张，29 张全带封面；分组名直接用接口给的（巅峰榜 5 / 地区榜 9 / 特色榜 11 / 全球榜 4），不再拿榜名关键词去猜（`RankInfo.group`），带「热歌榜」「新歌榜」字样的衍生榜因此不会被错抬进主榜。单榜的 `offset` 也在真翻页（实测 0/30 两批不重样），总曲数取 `data.totalNum`（飙升榜 100、热歌榜 300），界面据此知道什么时候翻到了头。榜单不再 60 多个全铺（三列宫格摊开是二十多行、四屏多的高度才看得到最后一个榜），只常驻第一组，其余靠「还有 N 组榜单」就地摊开；首页那两枚入口跳过来时替她摊好并滚到位。

## 构建

工具链装在 `~/dev`（免管理员）：Flutter 3.47 / JDK 21 / Android SDK。

```bash
bash build.sh
```

它会按 `pubspec.yaml` 的版本号同步「关于」页那行，`flutter build apk --release --split-per-abi`，再把 arm64 包命名成 `听歌小窝-<version>.apk` 拷到桌面。手动构建：

```bash
export JAVA_HOME="$HOME/dev/jdk21" ANDROID_HOME="$HOME/dev/android-sdk"
~/dev/flutter/bin/flutter pub get
~/dev/flutter/bin/flutter build apk --release --split-per-abi
```

### release 才踩得到的两处

debug 版不收缩代码也不收缩资源，所以这两种坏只在装进手机的版本里出现，而且坏得一点征兆都没有。

- `android/app/src/main/res/raw/keep.xml` —— audio_service 是运行时按名字查它那七枚控制图标的（`getResourceId → getIdentifier`），字节码里一次 `R.drawable` 引用都没有，资源收缩就把它们当没用的删干净了。图标 id 变成 0，推播放状态那一步直接抛「You must specify an icon resource id」：前台服务没起来、通知通道也没建，下拉里永远没有播放卡。
- `android/app/proguard-rules.pro` —— 桥被 idle 拆掉之后是靠反射把原生那半截 listener 装回去的（`MainActivity.reattachMediaListener`），对象是 `com.ryanheise.audioservice.**` 里那个类和它的嵌套接口，一个字节码引用都没有；R8 把名字改掉，这条修复就退回「原生答 missing」。

打完包核这两眼：`aapt2 dump resources` 里 `drawable/audio_service_*` 该有七枚，`build/app/outputs/mapping/release/mapping.txt` 里 `AudioService`、`AudioService$ServiceListener`、`AudioServicePlugin` 都该映射到自己。

### 会被就地增删的那份表，空的时候不能交 `const []`

`LibraryStore.songsFrom` 原来在文件读不出列表时 `return const []`，而交出去的这一份正是 `_by` 里被就地增删的底账。dart 的 `const []` 是不可变列表，于是新机器（收藏、最近播放、下载三份文件都还没落过盘）第一次 `recordRecent` 的 `removeWhere` 当场抛 `Unsupported operation: Cannot remove from an unmodifiable list` —— 而那一句卡在 `playAt` 的「地址已经装好」和「开口放」之间，换一条地址再来一遍还是同一句，整条队列一路跳过，看着像平台挂了。本机因为留着旧的 `recent.json`，读出来就是可写的，从头到尾没露过；安卓全新装机或清过数据同样中招，跟 Windows 没关系。

同一根因还带着三处：新机器点收藏（insert）、下载完成记账（removeWhere）、撤销「移出」（insert）。四处动的都是同一份 `_by[kind]`，所以改一句 `<Song>[]` 一起好 —— 判据以后照用：会被就地增删的那份底账，初始化必须是可变的；只对外给一份读不动的视图，那是调用口上另套 `List.unmodifiable`（`list()` 就是），不是靠返回值写 `const []`。钉它的是 `test/storage_test.dart` 里「库文件还没落盘时读出来的那一份」那组。

顺手补的取证：`[链] 「…」取不到声音` 那一行后面，如果异常是程序自己的错（`isOwnBug`），会紧跟一行 `[崩] 取证 · …`，带上 `package:lyric_music` 那几帧（最多三帧，一路跳歌只在第一首记）；全局崩溃处理器那两句同样带上。这类错从她那边只会回来一句没法行动的英文，抄一行日志就能定位到行。

### 桌面图标故意不做自适应图标，但整张必须铺满

`res/mipmap-{mdpi,hdpi,xhdpi,xxhdpi,xxxhdpi}/ic_launcher.png` 五张整幅铺满的方形 PNG（48/72/96/144/192）：圆盘画满整个宽度，四角用画面自己的夜色做一层虚化底补上，一个透明像素都不留。仓库里没有 `mipmap-anydpi-v26/ic_launcher.xml` 是被删掉的，别照安卓文档里的「最佳实践」补回来：

- 自适应图标是 108dp 画布只露中间 72dp，遮罩和缩放都由桌面说了算。华为/鸿蒙桌面会强制套圆角壳、还把图层放大到填满遮罩，一枚圆盘放进去出来就是方块，边上照样啃掉一块——前景层缩到多少都没用。
- 回落到 legacy 位图之后桌面按原样画，但它会先给普通位图垫一层白底再套圆角：四角留透明就是四个白角，跟旁边一格格的图标一比特别难看。所以「铺满」这件事得图自己做。
- 兼容别家桌面本该留 `mipmap-anydpi-v26`，可那正好把她的机器推回套壳那条路，两个要求互斥，所以按装机那台来。

## Windows 免安装版

同一套 Dart 代码也能在桌面上跑，产物有形态两份：一个 zip（解压双击 `lyric_music.exe`）和一颗自解压的单文件 exe（下面两节各说一种），都不用装任何东西（VC++ 运行库那三颗 DLL 一并抄进包里）。

构建走 GitHub Actions：仓库的 Actions 页 → `windows-portable` → Run workflow（`.github/workflows/windows-portable.yml`，只有 `workflow_dispatch`，一次出两份产物：`songbox-<version>-windows-x64-portable.zip` 和 `songbox-<version>-windows-x64-single.exe`）。

产物发在对应版本的 Release 上（tag 是 `v<版本号>`，文件名一律 ASCII —— Release 的直链会把中文名削掉）。桌面当前以 v0.8.38 那两颗为准：v0.8.37 的 Release 上原本也挂了这两颗，已撤下，就是上面那个 `const []` 的坑在未落过库文件的机器上每首都放不出，那版只剩 APK；已经装过桌面版的直接覆盖成新 exe。仓库是私有的，`github.com/…/releases/download/…` 那条直链不带登录态会回 `Not Found`，脚本取产物走 API（`GET /repos/masses27/songbox/releases/assets/<id>` 配 `Accept: application/octet-stream`）。上传同理不能用 `api.github.com` 那条路径（404），要用创建 Release 回包里的 `upload_url` —— 它指向 `uploads.github.com`，尾巴上挂着 `{?name,label}` 模板，得自己去掉模板占位、拼上 `?name=<ascii名>` 再 POST。

必须在 Actions 上编，本机编不了：`flutter build windows` 要能建符号链接，而这台机的账号既没有 `SeCreateSymbolicLinkPrivilege`，开发者模式也开不了（要写 `HKLM\...\AppModelUnlock`，得管理员）。runner 上这两条现成。

几个决定记在这儿，免得下次照安卓那套去猜：

- 仓库里不提交 `windows/` 那套 C++ 壳子，workflow 里 `flutter create --platforms=windows` 现造。日后 `flutter upgrade` 改壳子文件不会来来回回产生噪声 diff；改壳子也只能在这一步之后：`dart tool/patch_windows.dart` 一次改三处 —— 窗口标题（`L"听歌小窝"`，写成 `\u` 转义让 main.cpp 保持纯 ASCII）、启动尺寸、以及分辨率/DPI 变了以后跟不上的那几条消息。
- 窗口尺寸不再钉死模板那对 `1280×720`：模板会把逻辑尺寸再乘一次所在显示器的 DPI，低分辨率或高缩放的屏上开出来就是「窗口比屏幕还大」。现在按那块屏的工作区（已扣任务栏）取，启动时长宽都不超过工作区的 90%、也不超过 1280×720 换算成物理像素的那一档，居中摆好；最小可拖拽尺寸取 360×480（同样被工作区封顶），`WM_DPICHANGED`、`WM_DISPLAYCHANGE`、任务栏位置变了以后重新夹回工作区，正在最大化或最小化时不动它、等恢复那一刻再夹。几何算法都在 `tool/windows/window_geometry.h`，同一份头文件也拷进生成的 runner，所以 `tool/windows/window_geometry_test.cpp` 那 1000 组工作区/DPI 样本和真窗口消息断言验的就是装机那一份。补丁找不到模板锚点会直接失败，不会默默什么都不改。
- 声音换了后端：`just_audio` 官方只有 `android/` 和 `darwin/` 两条实现，桌面上每次播放调用都是 `MissingPluginException` —— 界面起得来、就是放不出。所以加了 `just_audio_media_kit`（libmpv），`main.dart` 里只在 `Platform.isWindows` 那一支注册，原来那句 `JustAudioBackground.init` 原样挪进 `else`；`player_service.dart` 的音频管道同理，安卓走的还是原来那条。libmpv 由 `media_kit_libs_windows_audio` 在构建时拉下来拷到 exe 旁边，构建那步会验它在不在包里。
- 数据落在 exe 旁边的 `data/`（`lib/util/app_paths.dart`）。桌面版 `getApplicationDocumentsDirectory()` 返回的是用户的「文档」根目录，不收敛就会把 `settings.json`、`library/`、`logs/` 全撒进她的文档里；`data/` 跟着包走，U 盘拷一份就是完整一套。旁边写不动时才退回应用支持目录。安卓落点不变。注意这个 `data/` 跟 Flutter 自己那个 `data/`（`app.so`、`flutter_assets`、`icudtl.dat`）是同一个目录，我们的 `logs/`、`library/` 就并排躺在引擎资源旁边——能用，但不体面，日后想分开就改 `AppPaths._desktopRoot()` 那一个名字。
- 安卓专属那几样在桌面上直接绕开，不去试：系统均衡器（`AndroidEqualizer` 走 MethodChannel）、下拉菜单那张播放卡的整条自检与接桥。均衡器那一页里「这台设备没有提供系统均衡器」那句就是给桌面版的。
- 已知短处：桌面上也没有媒体会话，切歌只能回应用里点。
- 验到哪一步了：0.8.35 那个包在本机起得来、界面和封面都正常，`libmpv-2.dll` 确实加载进了进程，旧版那句 `MissingPluginException(… just_audio.methods)` 不再出现，数据也确实落在 `data/` 而没碰「文档」。播放也真点过了：`data/logs/play-2026-10-27.log` 里三行 `[播]`（一首 B 站 192k、两首提前备好的 320k），队列自己往下走，`library/play_stats.json` 记到「阿刁」听到 371 秒（全长 374）并算完播、「米店」336 秒算完播——那是播放位置一路推进出来的数，不是点一下就能伪造的。`[崩]` 一条没有。剩最后一格没勾：耳机里到底有没有声，只有她耳朵能判。

## Windows 单文件版

zip 那份要用，就得一直留着那个文件夹：她桌面要么堆一层目录，要么放个快捷方式指进去。单文件那份把这些都省了——桌面永远只有 `听歌小窝.exe` 一颗（0.8.38 实测 20.8MB），双击就完事。

做法是启动器 + 尾巴：`tool/win_single/launcher.cs` 用 runner 上现成的 `csc.exe`（.NET Framework 4.8 自带，不额外装东西）编成一颗 211KB 的 exe，再把 zip 那一份整个接在它尾巴上。PE 只看头部那些节，尾巴上的字节当资源多余的部分忽略，所以这文件既是能跑的程序又是一份完整 zip；启动器按 zip 自己的 EOCD 往回算出尾巴起点（`blobStart = eocd绝对位置 - 中央目录长度 - 中央目录起始偏移`），把 blob 切出来解到 `%LOCALAPPDATA%\听歌小窝\`，再从那儿拉起 `lyric_music.exe`。payload 是 38 个条目（31 个文件 + 7 个目录项，压缩 20.6MB、解出来 47.2MB），第一次解压实测一秒左右；之后版本号和 `songbox-version.txt` 那枚戳记一致就直接跳过解压。

几条写死了的理由：

- 落点选 `%LOCALAPPDATA%\听歌小窝\` 而不是临时目录：数据是 `AppPaths` 按「exe 旁边的 `data/`」放的，跟着 exe 走，所以程序文件解在哪儿数据就在哪儿，固定落点 = 她的收藏和日志有个稳定的家。代价是不再「跟着文件走」——把这颗 exe 拷去别的机器，第一次会在对方机器上重新解一套空的。zip 那份还留着，要带走数据就拷整个文件夹。反过来也一样：哪天不想要了，删桌面那颗 exe 删不掉数据，`%LOCALAPPDATA%\听歌小窝\` 得整个删（收藏、播放统计、日志都在里面，别顺手清掉）。
- 升级只重写程序文件，她的东西一个字不碰：payload 里带 `data/` 开头的只有引擎自己那三样（`app.so`、`icudtl.dat`、`flutter_assets/**`），38 个条目里没有一个 `data/library`、`data/logs` 或 `settings.json`；`CopyOut` 又逐条按 zip 里的路径写、先落 `.new` 再换（半截 dll 是中断的更新把整套变成起不来的来路），够不着她的收藏、播放统计和日志。换新版 = 覆盖桌面那颗 exe，下次双击版本号对不上就重解一遍。
- 已经开着的时候不硬来：戳记是最新但进程在跑，就把那个窗口拉回前台，不再开第二个；戳记是旧的而进程在跑，直接提示「先把它关掉再点一次」退出——半覆盖正在运行的程序文件是版本混着用的来路。
- 图标走 `-win32icon:`，用和安卓同源那张 `mipmap-xxxhdpi/ic_launcher.png` 现拼的 ICO（16/24/32/48/64/96/128/192 八帧，202149 字节），编进启动器的资源里，桌面那颗 exe、任务栏、资源管理器预览都是它。为什么不提交现成的 `.ico`：logo 在 0.8.32-0.8.34 连着换了三次，二进制文件正是下次换标会忘记重生的那种。zip 那份里 `lyric_music.exe` 带的还是 Flutter 模板那颗图标（runner 是 `flutter create` 现造的，没往里塞图标），要它好看就照以前那样在外面配快捷方式 —— 这也是单文件版顺手解决掉的一件事。
- 三份都实测 `Get-AuthenticodeSignature = NotSigned`（runner 上没有证书），第一次运行 Windows 拦一下属正常：弹的那张「已保护你的电脑」要按「更多信息」才露出「仍要运行」。这跟单文件版没关系，zip 里那颗 exe 一样。
- 单文件这份本机验到的是：桌面双击 → 进程起在 `%LOCALAPPDATA%\听歌小窝\lyric_music.exe`（不是桌面那颗），窗口标题 `[听歌小窝]`，`libmpv-2.dll` 确实加载，日志接着往 `data\logs\` 里写 `[起]`；已经在跑的时候再点一次，进程数不变，只把窗口拉回前台，也不重解 —— 前几条是 0.8.36 那两颗点出来的，「不重解」这一条 0.8.38 用 `/dir:` 指到刚解压好的那份又走了一遍，启动器日志里就是那句 `stamp matches, no unpack`。尾巴接的就是那份 zip 本体：run 8 的产物 21,849,150 = 启动器 215,552 + 免安装包 21,633,598，尾巴上那 21,633,598 个字节跟 zip 本体逐字节相同（两边 SHA256 一样）、起点正落在 `PK` 上，启动器自己那行日志印出来的 `blobStart` 也是 215552；包体里 31 个文件、`lyric_music.exe` 和 `libmpv-2.dll` 都在。run 6 那次还逐个 SHA256 比对过解出来的文件与 zip 里的条目，0 处不一致。播放那一格 0.8.38 补上了：让程序在一个 `data/library/` 里一个文件都没有的目录里冷启动（就是她另一台机器上「一首都没放过」的那个状态），点「播放已加载 50 首」，日志里 `17:47:56 [播] 「画」开始播放（第 0:00，现取 192k）` 之后 `[链]`、`[崩]`、`[跳]` 一条都没有，`recent.json` 当场落盘 —— 0.8.36 那份卡的正是这一步的 `Cannot remove from an unmodifiable list`。剩最后一格没勾的还是耳机里到底有没有声，只有她耳朵能判。
- 启动器补了版本资源（五条 assembly attribute，两个版本号都取那句被 workflow 改写的 `Version`）：run 8 的 exe 属性→详细信息实测 `FileVersion=0.8.38`、`ProductVersion=0.8.38`、产品名和说明都是「听歌小窝」，不再是一颗 20MB 的无名 blob。这一句能对上，靠的是 workflow 改成按正则匹配 `Version` 行本身 —— 以前它钉死上一版的字面量，一旦 `launcher.cs` 里的默认值已经等于要编的那一版，改写就静默空转，下一版会拿上一版的戳记出货。里面那颗 `lyric_music.exe` 带的还是 Flutter 模板那套（`FileDescription=lyric_music`、`FileVersion=0.8.38+51`），那个壳子是 `flutter create` 现造的，不去动它。

启动器源码里那三行 `\u` 转义的汉字不是凑字数：`csc` 读没 BOM 的文件按各机 ANSI 代码页解码，源码里塞汉字哪天就编成乱码——和 `main.cpp` 的窗口标题同一个理由。调试开关 `/dir:<路径>`（解到别处）和 `/check`（只解压不启动）、`/log:<路径>`（winexe 没控制台，话只能写文件）留给 CI 和本机复现用，她双击时一个都不会碰到。

## 目录

- `lib/music_sdk/` —— 各家曲库的匿名接口（网易云的 weapi 签名在本机算，不落任何凭证）
- `lib/player/` —— just_audio + 后台服务，队列、换源、断网重试、播完/停住的进度兜底、播放卡取证与接桥都在这儿
- `lib/library/` —— 本机数据：收藏、自建歌单、播放历史、口味画像（推荐吃这个，不联网）
- `lib/download/` —— 下载与均衡器
- `lib/util/` —— 日志、封面地址与本地封面文件、人话化错误、原生通道、数据落点（`app_paths.dart`，安卓与桌面各归各处）
- `lib/ui/` —— 页面、组件、色板
- `third_party/songbox_audio_background/` —— just_audio_background 0.0.1-beta.17 的副本，只为把卡上「上一首/下一首」接到应用自己的切歌（上游接的是它自己的 `skipToQueueItem`，而本项目一首一首装 AudioSource，队列里永远只有一项）。改动只有三处：两个静态钩子、`skipToNext/Previous` 先走钩子、控件表在钩子装着时放行那两个键。升上游版本时这三处要重新对齐，`test/card_skip_seam_test.dart` 会先响。
